## `npm run shot` の絵との食い違い —— sRGB の伝達関数 1 回ぶん

**同じ種・同じ時刻で、CPU 側の絵が systematically 暗い**（`npm run shot -- ground --time 0.064`）。
草の上面をぶつけると:

| | 赤 | 緑 | 青 |
| --- | --- | --- | --- |
| `tools/raster.ts`（CPU） | 37 | 100 | 20 |
| ブラウザ（three） | 106 | 168 | 79 |
| CPU の値に sRGB の符号化を掛けた値 | 106.3 | 168.1 | 79.1 |

`1.055 * x^(1/2.4) - 0.055` を通すと **3 チャンネルとも ±1 で一致**します。
three の `WebGLRenderer` は `outputColorSpace = SRGBColorSpace` が既定で線形 → sRGB を
掛けますが、`raster.ts` は線形の値をそのまま 8 ビットへ丸めています（`raster.ts:243`）。

**この食い違いは直しました**（`raster.ts` の `srgb()`。混ぜるのも three と同じく
符号化したあとにしてあります）。直したあとに同じ絵を撮り直して突き合わせると、
地面の代表色は **両方とも rgb(106,168,79) と rgb(94,156,65)** で一致します。
判定は `test/shot.test.ts` が画素の値で持っています（正面 239 / 上面 255 /
底面 188 / 半透明 119）。

空は別経路（ブラウザは `sky.ts` の天球 GLSL、CPU は `daynight.ts` の 2 色の勾配）なので、
そもそも一致しません（CPU rgb(16,57,146) / ブラウザ rgb(46,96,181)）。

### 撮り方で踏んだもの（次に動かす人へ）

- **`page.mouse.click()` を使わないこと。** あれは先にポインタを動かすので、**ポインタロック中は
  視点が飛んで狙いが外れます**（`target -` になって `edits 0`。2 回落としました）。
  **`mouse.down()` / `mouse.up()` で押して離すだけ**にすること。
- **どちらが「下」かを決め打ちしないこと。** `movementY` を増やす向きが下とは限りません。
  **`#debug` の `target` の行を読みながら、地面を狙えるまで動かす**ほうが速く着きます。
- **平原は草むらだらけです。** 先に左クリックで刈らないと耕せません（草むらは `tilled()` が
  `AIR` を返す —— **正しい挙動**で、不具合ではありません）。
- 撮る道具は使い捨てのスクリプトで、**リポジトリには置いていません**（`tools/browsershot.mjs` は
  5 枚の定番だけ。クリエイティブの一覧と耕すところは、そのつど書いたほうが安いという判断です）。

### 撮り方で分かったこと（9 枚目の続き）

- **`page.mouse.move()` では視点が動きません**（ポインタロック中の `movementX/Y` が出ない）。
  `main.ts` が読むのは `mousemove` の `movementX/Y` だけなので、
  **`document.dispatchEvent(new MouseEvent("mousemove", { movementY: 20 }))` を直に投げる**のが確実です。
  9 枚目の README にある「`page.mouse.click()` を使わないこと」はそのままで、**押して離すのは
  `mouse.down()` / `mouse.up()`、視点は合成イベント**、という組み合わせになります。
- **一覧からホットバーへ入れるなら、クリックの往復ではなく `Shift`+クリック**にすること。
  掴んで枠に置くと**入れ替え**になって手に前の中身が残り、**次に一覧を押した 1 回が
  「捨てる」に化けます**（`pressCreative()` の規則。実際に 2 度落としました）。
  **先に枠を空にしてから `Shift`+クリック**すれば `inventory.add()` が空いた枠に直に入れます。
- **刈ると狙いが外れます**（草むらが消えたぶん光線が抜ける）。刈ったあとに
  `target` が `-` になったら、地面に当たるまでもう少し下を向くこと。
