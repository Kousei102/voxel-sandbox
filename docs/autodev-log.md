# 自動実装ループの記録（読まなくてよい）

**これは `AUTODEV.md` の「6. 記録」の退避先です。** キューではないので、ループは毎周
読む必要がありません。**必要になるのは 2 つのときだけ:**

- **同じものをまた検討しそうなとき** —— 「見送ったもの」に理由が 1 行あります
- **同じ形でまた落ちたとき** —— 「差し戻し」に、何を仕様書に書き忘れて落ちたかがあります

いま取るものは `AUTODEV-QUEUE.md`、手順は `AUTODEV.md`。

書き方は 1 周 1 節で、次の形にしてください（**要約しないこと**。次の周が読むのは
「なぜそう決めたか」で、結果だけなら `git log` にあります）。


## 2026-09-01 — 1. 砂と砂利が落ちる（重力ブロック）。C（実装）の周

- **取ったもの**: `src/gravity.ts`（新規）/ `blocks.ts` の `fallsDown()` と `falls` フラグ /
  `breaking.ts` と `placing.ts` から 1 行ずつ。**ID は 0 個**（新しいブロックもアイテムも足していない）。
- **なぜこの形にしたか（次の周が同じ道を通らないために）**:
  - **手本は `liquids.ts` と `quenched()` の対**。規則（**どの ID が**落ちるか）は
    `blocks.ts` の表 1 本、**どのマスに**効くかは `gravity.ts` 1 か所、呼ぶのは
    `breaking.ts` / `placing.ts` の 1 行ずつ。**`main.ts` と `world.ts` は 1 行も触っていない**
    —— 配線すら要らないのは、判断が全部 `gravity.ts` に閉じたからです。
  - **落下は即時（1 フレームで着地まで）。** 落下エンティティを作ると `droprender.ts` の
    ような描画が要り、**この環境では見た目を確かめられません**（`CLAUDE.md`）。
    本家と違うので `TUNING.md` に 1 行残してあります。
  - **`world.update()` と生成器からは呼びません。** 毎フレーム走らせると
    `test/world.test.ts` の p99 に乗り、生成直後の砂漠の砂と洞窟の天井の砂利が
    勝手に崩れて `test/worldgen.test.ts` の見え方まで変わります。
    **つまり「生成された浮いた砂」は掘るまで落ちません** —— これは仕様です。
  - **`breaking.ts` の `autoBreak()` からは呼びません。** あそこは `world.ts` が
    そのマスを消している**途中**でブロックがまだ残っており、空振りするだけ。
    **呼ばない理由をコメント 1 行で残してあります**（次の周が「呼び忘れ」と誤読しないため）。
  - **書く順は「先に落ちる先へ書き、成功したときだけ元のマスを消す」。** 逆にすると
    `setVoxel` が false を返したときに砂が消えます（`liquids.ts` の裏返し）。
    チェック役が**未読み込みの列を凍結して実際に確かめ**、`moved=0` で無変化＝
    砂が消えも増えもしないことを取っています。
- **見送ったもの**: 落下ダメージと落ちる速さ —— 落下エンティティが要り、見た目を
  確かめられない（`TUNING.md` 行き）。**松明を運ぶこと** —— 砂が下がると既存の
  `breakUnsupported` で壊れるのが本家と同じで、重力の側に支えの話を持ち込むと
  `supportFace` と二重管理になります。
- **差し戻し**: **0 回。** 仕様書の「2. 触るファイル / 触らないファイル」と
  「6. 禁じ手」がそのまま守られていました（B の周で 7 項目を埋めた効き目）。
- **チェック役が別に見つけたこと**: 実装側の報告にあった「2286 → 2307」は正しく、
  **仕様書の『2285 件』が 1 件古かった**（`test/docs.test.ts` が `AUTODEV-SPEC.md` の
  行数を見始めたぶん）。**件数は仕様書ではなく `npm test` から取ること。**
- **枠**: **変化なし。** 1..63 の空き 9 / 111..255 の空き 145 のまま（ID を使っていない）。
  `main.ts` 1373 行のまま（触っていない）。テスト 2286 → **2307 件**（+21）。

## 2026-09-01 — A（棚卸し）の周。`AUTODEV-QUEUE.md` を作った

- **基準**: 本家のバージョン順（Alpha → Beta → 正式版）で、まだ無いものを上から取る。
  **次の A の周でも変えないこと**（`AUTODEV.md` の A-1）。
- **取ったもの**: 10 件。並びは `AUTODEV-QUEUE.md`。
  上 3 件（重力ブロック・大きいチェスト・道具の耐久値）が**番号を 1 つも使わない**ので先頭で、
  4..6（剣・ハサミ・作物）が番号を使うぶん、7..10（鶏・牛・クモ・スケルトン）は
  **見た目がユーザーにしか確かめられない**ので最後。取りやすさで並べたのではありません。
- **数え直して分かったこと**: **剣が 1 本も無い。** 道具はツルハシ・斧・シャベルの 3 種だけで、
  攻撃力は `mobs.ts` の `TOOL_ATTACK`（斧 3 > ツルハシ 2 > シャベル 1・階層ごとに +0.5）。
  本家で最初期からある物がまるごと抜けていたので、`ROADMAP.md` にも載っていませんでした
  —— **「入れたいもの」の一覧より、コードを数えるほうが速く見つかる**という例です。
- **見送ったもの（理由 1 行ずつ）**:
  - **水流・溶岩流** —— 1 フレームの予算（生成 3ms / メッシュ化 6ms）に流体の更新を
    載せる設計がまだ無く、1 周では閉じない。**黒曜石の導線はバケツで足りている**
    （`rules/blocks-shapes.md` の `quenched()`）ので、急ぎでもない。
  - **防具** —— 番号を 12〜16 個食ううえ、インベントリ画面に枠を足す（DOM 側）ので 1 周に入らない。
    **革（牛・8 番）が先**に要る。
  - **経験値とエンチャント** —— 手触りの数値が多く、ユーザーと決めることが多い（`TUNING.md` 行き）。
  - **レッドストーン** —— 状態の伝播が丸ごと新しい仕組みで、1 周では閉じない。
  - **醸造とポーション** —— **効果（状態異常）の器が `vitals.ts` に無い**。毒しかないので、
    先に「効果」という枠を作る周が要る。
  - **ネザークォーツ** —— 番号を 2 個使うのに使い道がレッドストーン待ちで、いま入れても飾り。
  - **天候（雨・雪）** —— 描画とパーティクルが要り、この環境では確かめられない（`CLAUDE.md`）。
  - **村と村人** —— 構造物 + モブ + 取引の 3 つが同時に要り、1 周に入らない。
  - **TNT と爆発** —— 球状にブロックを消す処理がメッシュ化の予算に効く。重力ブロック（1 番）の
    あとなら形が見えるので、**次の A の周で数え直すこと。**
