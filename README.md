# Voxel Sandbox

ブラウザで動くボクセルサンドボックス。無限に広がる地形を歩き回って、ブロックを壊したり置いたりできます。
Vite + TypeScript + three.js のみで、外部アセットもゲームエンジンも使っていません。

**→ https://kousei102.github.io/voxel-sandbox/**

```bash
npm install
npm run dev      # http://localhost:5173
```

## 操作

| キー | 動作 |
| --- | --- |
| `W` `A` `S` `D` | 移動 |
| `Space` | ジャンプ（水中では浮上、飛行中は上昇） |
| `Shift` | ダッシュ |
| `F` | 飛行の切り替え（`Ctrl` で下降） |
| 左クリック（長押し） | ブロックを掘る |
| 右クリック | ブロックを置く / 作業台・かまど・チェストを開く |
| 右クリック（長押し） | 食べ物を食べる（1.6 秒） |
| 中クリック | 狙ったブロックを手に持つ |
| `1`–`9` / ホイール | ホットバーの選択 |
| `E` | インベントリ（2x2 のクラフト） |
| `Q` | 持っているものを 1 個捨てる（地面に落ちるので拾い直せます） |
| `Ctrl`+`Q` | 持っている山を丸ごと捨てる（`Shift`+`Q` でも可） |
| `F3` | デバッグ表示 |
| `Esc` | メニュー（保存もここから） |

サバイバルでは掘ったものだけが手に入ります。素手で原木 → 板 → 棒と作り、作業台を置いて道具を作ると
掘れるものが増えていきます（石は木のツルハシから、鉄鉱石は石、金とダイヤは鉄のツルハシから）。
石炭が採れたら棒と合わせて松明になります。松明は洞窟でも夜でも暗くならないので、
潜るならまず石炭を探してください。床にも壁にも付けられます（天井には付きません）。
高いところから落ちたり、水中で息が切れたりすると体力が減り、0 になると**持ち物を全部その場に落として**
リスポーンします。落としたものは 5 分で消えるので、取りに戻ってください（奈落で死んだぶんは戻せません）。
夜になると外にゾンビが湧き、暗い洞窟には昼でも湧きます。松明を置いたところには湧かないので、
潜るときも夜を越すときも明かりが要ります。豚と羊は明るい草の上に居て、倒すと生豚肉と羊毛を落とします。生豚肉はかまどで焼くと焼き豚になり、
右クリックの長押しで食べて空腹を満たせます。
メニューの「モード」でクリエイティブに切り替えると、無敵・即掘り・アイテム無限になります。

編集内容とインベントリは localStorage に自動保存され、次回はシードと時刻ごと復元されます。
メニューでシードを入れ替えれば別の世界を作れます。
昼夜は 1 周 20 分ですが、待たずに見たいときはメニューの時刻スライダーを動かしてください。

## 実装

```
src/
  constants.ts  チャンクサイズ・描画距離・フレーム予算
  blocks.ts     ブロック定義（色・不透明度・当たり判定・硬さ）
  items.ts      アイテムと道具の定義、ブロックのドロップ
  mining.ts     採掘時間の計算と進行
  inventory.ts  36 スロットのインベントリ
  crafting.ts   レシピと盤面の照合
  craftscreen.ts インベントリ画面の判断（掴む・置く・配る・閉じるときの返却）
  vitals.ts     体力・落下ダメージ・息
  storage.ts    localStorage へのセーブとロード（差分だけ）
  noise.ts      シード付き Perlin ノイズ
  worldgen.ts   高さマップ・洞窟・木・鉱石
  biomes.ts     気温と湿度からバイオームを決める
  lighting.ts   スカイライトとブロックライトの伝播（BFS）
  mesher.ts     greedy meshing と AO・光
  meshbuild.ts  メッシュの配列を three の BufferGeometry に載せる
  chunk.ts      16^3 のボクセル配列とその GPU バッファ
  world.ts      チャンクの生成・メッシュ化・破棄のスケジューリング
  physics.ts    AABB の移動と衝突解決（プレイヤーとモブで共有）
  player.ts     一人称の移動と入力
  raycast.ts    ボクセル格子のレイトラバース（DDA）
  mobs.ts       モブの表・AI・湧き・戦闘・ドロップ
  mobmesh.ts    モブのモデル（箱を積んで頂点配列にする）
  mobrender.ts  モブの three 側（Group / Mesh / 毎フレームの同期）
  drops.ts      落ちたアイテムの物理・寿命・統合・拾う判定
  smelting.ts   精錬の表（何が何になる・何が何秒燃える）とかまどの進み方
  furnaces.ts   置いてあるかまど（位置 → 中身）とそのセーブ
  droprender.ts 落ちたアイテムの three 側（Mesh と毎フレームの同期）
  daynight.ts   時刻から空の色・明るさ・太陽と月の位置を出す
  sky.ts        カメラに追従する天球と太陽・月・星
  terrainshader.ts 2 系統の光を合成する数行の GLSL
  crack.ts      採掘中のひび割れ（実行時生成テクスチャ）
  sfx.ts        何を・いつ・どんな数値で鳴らすか
  audio.ts      WebAudio で波形を合成して鳴らす
  ui.ts         ホットバーとデバッグ表示
  inventoryui.ts インベントリとクラフトの画面
  main.ts       描画ループと入力
```

要点を 3 つ。

**greedy meshing** — チャンクを 3 軸それぞれのスライスに分け、隣り合う同じ面を長方形にまとめます。
16x16 の平らな床は 512 枚の三角形ではなく 2 枚になります。ブロック ID・向き・AO・2 系統の光量を
整数 2 本に詰め、それが完全に一致する面だけを統合しています（47 ビットあって 1 本には収まりません）。

**AO（アンビエントオクルージョン）** — 面の四隅ごとに、外側の 3 マス（辺 2 つと角 1 つ）が埋まっているかで
0〜3 段階の陰影を決め、頂点色に焼き込んでいます。three のライトを 1 つも置かずに立体感が出るのはこれのためです。
そのぶんマテリアルは `MeshBasicMaterial` 2 枚（不透明用・半透明用）で済んでいます。

**光** — 2 系統あります。スカイライトは「真上に遮るものが無いボクセル」が光源で、そこから 6 方向へ
1 マスにつき 1（水中は 3）減衰しながら BFS で広がります。洞窟は光源から遠いので暗く、入口の周りだけ
光が染み込みます。深さで一律に暗くする方式だと、崖の途中の洞窟や木の下まで真っ暗になってしまうので、
実際に光を伝播させています。ブロックライトは松明が光源で、広がり方は同じですが**昼夜の影響を受けません。**
ブロックを置いたり壊したりしたときは、消える光と増える光をそれぞれ BFS でたどって差分だけ塗り直します。

2 つを 1 本にまとめてしまうと「昼夜で暗くしてよい光か」の区別が消え、夜や洞窟で松明まで暗くなります。
そこでメッシュには 2 成分のまま載せ、最終的な明るさ `max(スカイ × 昼夜の色, ブロック)` は描画時に
GPU で決めています。このゲームで GLSL を書いているのはここ（3 行）と天球のグラデーションだけです。

**昼夜サイクル** — 1 周 20 分（Minecraft と同じ）。空と地平線とフォグの色が朝焼け・昼・夕焼け・夜と移り、
太陽と月が反対側を回り、夜は星が出ます。地形の明るさは時刻に応じた色を 1 つ渡すだけで、それが
スカイライトに掛かるので**メッシュを作り直さずに**夜になります。真夜中でも 28% までしか落としません
（松明を持たずに夜を迎えたときに何も見えなくならないように）。
時刻の計算は `daynight.ts` に閉じていて、three の `Color` と `Vector3` しか使わないためテストで検証できます。

**松明** — Minecraft と同じ石炭 1 + 棒 1 で 4 本。明るさ 14 で、1 マスごとに 1 ずつ暗くなります。
クリックした面に貼り付くので、床にも壁にも置けます。支えにしたブロックを壊すと一緒に壊れます。

柄と炎の箱を積んで作っていて、greedy meshing の統合対象からは外れています（立方体でないブロックを
足すならこの経路です）。壁掛けの向きはボクセルのメタデータではなく**別のブロック ID** で表しています。
ID は 63 まで使えて余裕があるぶん、データを `Uint8Array` のまま、面の統合キーもそのままにできます。
プレイヤーから見て 1 種類であることは `variantOf` が引き受けていて、名前もドロップもアイテム欄も
床置きの松明に揃います。壁掛けの柄が斜めに見えるのは、少しずつ迫り出す 3 段の箱による近似です
（本物の斜めにすると法線が軸に平行でなくなり、面の裏返りを数値で検証できなくなります）。

**バイオーム** — 気温と湿度の 2 つのノイズで、砂漠・平原・森・針葉樹林・雪原の 5 つに分かれ、
そこに高さによる上書き（海・浜・山）が掛かって 10 種類になります。地表と地下 3 ブロック・
木の生えやすさ・木の種類がバイオームごとに変わり、砂漠には木の代わりにサボテンが生えます。
1 周 600 ブロックほどなので、歩いていると数分で景色が変わります。現在地は <kbd>F3</kbd> に出ます。

気候と高さの役割は分けてあります。高さの判定を気候の側に混ぜると、「高さを決めるのに
バイオームが要り、バイオームを決めるのに高さが要る」という循環になるためです。

雪が積もるかどうかは高さではなく気温で決めています。高さだけで決めていたときは、
砂漠から生えた山の頂上が即座に雪になり、砂と雪が 4 ブロックまで近づいていました。
いまは暖かい土地の山は雪をかぶらず岩肌になるので、砂漠と雪のあいだにはかならず
45 ブロック以上の「雪の降らない土地」が入ります（気温が 1 ブロックで動く量に上限があるため）。
判定は `biomes.ts` に閉じていて、出現割合と「砂漠が雪と隣り合わないこと」をテストで見ています。

**採掘とクラフト** — 掘る時間は Minecraft と同じ式（`硬さ × (適正なら 1.5 : 5) / 道具の速さ`）で、
石は素手なら 7.5 秒・木のツルハシなら 1.13 秒です。種類の合わない道具では速くならず、階層の足りない
道具（石のツルハシでダイヤ鉱石など）は掘れてもアイテムが出ません。レシピは盤面とレシピの両方から
空の行・列を落として比べるので、盤面のどこに置いても揃い、斧のような左右非対称の形は反転しても作れます。
鉄と金の鉱石は鉱石のまま落ちるので、インゴットにするにはかまどで焼きます（下記）。

**体力** — 落下は「空中での最高到達点 − 着地点」で、3 ブロックまで無傷、そこから 1 ブロックにつき 1 減ります
（Minecraft と同じ）。水面に落ちれば無傷です。息は 15 秒で、切れると毎秒 2 減ります。

**空腹** — ハートの下の肉ゲージ 10 個。走ると 40m、歩くと 400m で 1 個減り、掘る・殴る・回復するときにも
減ります（減り方は Minecraft と同じ式です）。食べ物を持って**右クリックを長押し**すると 1.6 秒で食べ、
咀嚼音が鳴ります。焼き豚がいちばん強く、腐った肉は空腹こそ戻りますが弱い毒付きです。
**ゲージが 9 個を切ると体力が自然回復しなくなり**、空になると 4 秒ごとに 1 減ります。ただし
**空腹だけでは死にません**（体力 1 で止まります）。毒も同じで死にません。3 個以下になると走れなくなります。

**モブ** — 豚・羊・ゾンビの 3 種類。豚と羊は明るい草の上に、ゾンビは暗いところ（夜の地表と洞窟）に湧きます。
湧くかどうかを決める明るさは `max(スカイライト × 昼夜の明るさ, ブロックライト)` で、**画面を描いている
シェーダとまったく同じ式**です。だから「明るく見えるのに湧く」場所ができません。この 1 本で
「夜の外は危ない・松明を置いたところは安全・洞窟は昼でも危ない」が同時に決まります。豚と羊だけは
昼夜を掛けない生のスカイライトで見ます（掛けると夜のあいだ 1 体も湧かず、朝には世界が空になるため）。

ゾンビは 4.6 m/s で、歩き（5.2）よりわずかに遅い程度です。歩き続ければ引き離せますが、立ち止まると
追いつかれます。接触で体力が 2 減り、何体居ても無敵時間を共有するので囲まれても入る量に上限が付きます。
1 ブロックの段差は跳んで越えますが 2 段は越えられないので、壁で囲えば防げます。朝になって真上が
完全に空いているところに居ると燃えます（木の下・屋根の下・水中では燃えません）。倒すと豚は生豚肉、
羊は羊毛、ゾンビは 6 割の確率で腐った肉を落とします。肉は焼いて食べられます（上の「空腹」）。

モブは保存しません。地形と同じで、作り直せるものは持たない方針です。当たり判定と移動はプレイヤーと
`physics.ts` を共有していて、AI・湧き・戦闘の数値は `mobs.ts`、three に触るのは `mobrender.ts` だけです。
形は軸に平行な箱として作り、回転は `Object3D` に任せています（斜めの面を作ると、面の裏返りを
数値で検証できなくなるためです）。

**落ちたアイテム** — 掘ったブロックも倒したモブのドロップも、その場に小さな立方体として落ちます。
回りながら軽く上下に揺れ、近づくと拾えます。持ち物がいっぱいなら**拾えなかったぶんは地面に残ります**
（黙って消えることはありません）。同じアイテムどうしは近づくと 1 山にまとまり、5 分で消えます。
Q で捨てたものは視線の向きへ飛び、2 秒間は自分で拾い直しません。水には浮きます。

モブとは逆に**落ちたアイテムは保存します**。シードから作り直せるモブと違って、掘って出したアイテム
そのものだからです。判断（物理の数値・寿命・拾う距離・統合）は `drops.ts`、three に触るのは
`droprender.ts` だけで、新しいシェーダは 1 行も足していません。

**かまどと精錬** — 丸石 8 個で作れます。材料・燃料・焼き上がりの 3 枠で、鉄鉱石と金鉱石を
インゴットに、砂をガラスに、丸石を石に、生豚肉を焼き豚にします。燃料は石炭がいちばん長持ちし、
板や棒でも燃えます（石炭を見つける前でも鉄を焼けるようにしてあります）。
**画面を閉じていても焼けます**し、火が点いている間は光ります。壊すと中身は地面に出ます。

置いたかまどは「位置ごとに中身を持つブロック」で、地形の差分とは別に保存しています。

**チェスト** — 板 8 個で作れます。27 枠（プレイヤーの収納と同じ）で、入れたものは
画面を閉じても中に残り、**壊すと全部地面に落ちて拾い直せます**（クリエイティブでも落ちます）。
かまどと違って取り出し専用の枠が無く、全部の枠に出し入れできます。Shift + クリックで
インベントリとの間を一発で行き来できます。

かまどが作った器（位置ごとに中身を持つブロック）にそのまま乗っていて、判断は `chests.ts`、
画面は同じ `CraftScreen` です。**画面ごとにクラスを分けていない**ので、掴む・配る・
シフトクリック・数字キー・ドラッグ配分がそのまま効きます。

**音** — 外部アセットは使わず、**波形も実行時に合成しています**（テクスチャと同じ方針）。
音色はブロックの材質（草・土・砂・石・木…）× 出来事（掘る・壊す・置く・歩く）の 2 段で決まるので、
出来事ごとに全ブロックぶん用意する必要がありません。柔らかい材質ほどローパスを低くしてこもらせています。

足音は時間ではなく**歩いた距離**で刻みます。ダッシュすれば自然に速くなり、壁に押し付けて足踏みしても
鳴りません。掘っている間のコツコツ音は採掘の進み具合で刻むので、硬いブロックほど間隔が空きます。
水中は全体をローパスでこもらせます。モブの声は種類ごとに音を用意せず、音程の倍率だけ変えています。

「何を・いつ・どんな数値で鳴らすか」は `sfx.ts` にあり、`AudioContext` に触るのは `audio.ts` だけです。
おかげで音の判断はヘッドレスでテストでき、耳で確かめないと分からないのは音色そのものだけになっています。
音量はメニューのスライダーで、0 にすれば完全に切れます。

**フレーム予算** — 地形生成もメッシュ化も 1 チャンクあたり約 1ms かかります。個数で区切るとフレームが飛ぶので、
`world.update()` は時間（生成 3ms・メッシュ化 6ms）で区切って続きを次のフレームに回します。
また、メッシュ化には隣接する 8 列のボクセルが必要なので、ボクセルだけは描画距離より 1 リング広く用意し、
隣が揃っていないチャンクは同期生成せずに後回しにしています（ここを手抜きすると数十 ms のスパイクが出ます）。

## 確認

```bash
npm test       # 生成・メッシュ化・光・物理・昼夜・採掘・インベントリ・クラフト・精錬・体力・モブ・落とし物・音の検証（912 項目）
npm run bench  # 生成とメッシュ化の速度計測
npm run build  # 型チェック + 本番ビルド
```

`npm test` は WebGL 無しで走ります。頂点の巡回順と法線の一致（ずれると裏面カリングで面が消える）や、
描画距離内にメッシュ化されないチャンクが残らないことなど、画面を見ないと気付きにくい部分を押さえています。
実際の見た目の確認はブラウザで行ってください。

フレーム時間の判定は壁時計の最悪値ではなく、そのマシンでチャンク 1 個を生成する時間を実測し、
それを単位にした中央値と p99 で見ています。最悪値は GC の単発スパイクで簡単に跳ねるので、
マシンの速さが違っても同じ意味になるようにしてあります。

計測例（Node 22 / WSL2）:

```
generateChunk   1.09 ms/チャンク
buildChunkMesh  1.28 ms/チャンク (992 三角形)
world.update    平均 3.4 ms / 最悪 10.7 ms（歩行中のストリーミング込み）
```

同じコードでも 1 回ごとに 2 割ほど振れるので、比べるときは数回まわして中央値を見てください。

## デプロイ

`master` に push すると `.github/workflows/deploy.yml` が走り、`npm ci` → `npm test` → `npm run build`
を通ってから `dist/` が GitHub Pages に配信されます。テストが落ちればデプロイはされません。
手動で回すときは Actions タブの "Run workflow"、または `gh workflow run deploy.yml` です。

サーバーも DB も無く、セーブは localStorage なので、置くものは `dist/` の 3 ファイル
（`index.html` と JS・CSS 各 1 つ、合計 511 kB / gzip 134 kB）だけです。JS のほとんどは three.js 本体で、
初回だけ一括ダウンロードになります。

`vite.config.ts` の `base: "./"` は**相対パスにするためのもの**です。GitHub Pages は
`https://<user>.github.io/<repo>/` というサブディレクトリ配信なので、既定の `base: "/"` のままだと
アセットの参照先が `/assets/...` になって 404 になります。ここを絶対パスに戻すなら、
リポジトリ名を含む `base` を指定してください。

他のホスティング（Cloudflare Pages / Netlify / Vercel、あるいは nginx で `dist/` を配るだけ）でも
同じものがそのまま動きます。ビルドコマンド `npm run build`、出力ディレクトリ `dist` を指定するだけです。

## 調整できるところ

洞窟の暗さは `src/constants.ts` の `AMBIENT_LIGHT`（スカイライト 0 の場所の明るさ、既定 0.16）と
`LIGHT_FALLOFF`（暗がりへの落ち込みの急さ、既定 1.4）で決まります。暗すぎると感じたら
`AMBIENT_LIGHT` を 0.25 くらいまで上げてください。

昼夜は `DAY_LENGTH_SECONDS`（1 周の実時間、既定 1200 秒）と `NIGHT_BRIGHTNESS`（真夜中の明るさ倍率、
既定 0.28）で決まります。どちらも松明の明るさには掛からないので、夜を暗くしても松明を持っていれば
歩けます。松明の明るさそのものは `src/blocks.ts` の `TORCH_LIGHT`（既定 14）です。

落下ダメージの閾値・息の長さ・自然回復の速さは `src/vitals.ts` の先頭にまとまっています。

鉱石の出現率は `src/worldgen.ts` の `ORES`（湧きやすさと出てよい高さの上限）です。既定では石炭が石の
1.5%、鉄が 1.0%、金が 0.2%、ダイヤが 0.05% になります。掘る時間とドロップは `src/blocks.ts` の
`hardness` / `tool` / `minTier` と `src/items.ts` の `DROPS`、レシピは `src/crafting.ts` の `RECIPES` です。

`RENDER_DISTANCE`（描画距離）と `CHUNK_LAYERS`（世界の高さ）も同じファイルにあります。
地形の性格は `src/worldgen.ts` の `heightAt()` にまとまっていて、大陸・丘・尾根の 3 つのノイズを混ぜています。
バイオームの境目・地表のブロック・木の生えやすさは `src/biomes.ts` の `BIOMES` と気候のしきい値です。
ブロックを増やすときは `src/blocks.ts` に定義を足して `PALETTE` に並べれば、ホットバーにも出ます。
