# Voxel Sandbox

ブラウザで動くボクセルサンドボックス。無限に広がる地形を歩き回って、ブロックを壊したり置いたりできます。
Vite + TypeScript + three.js のみで、外部アセットもゲームエンジンも使っていません。

**→ https://kousei102.github.io/voxel-sandbox/**

```bash
npm install
npm run dev      # http://localhost:5173
```

## 操作

| キー | 動作 |
| --- | --- |
| `W` `A` `S` `D` | 移動 |
| `Space` | ジャンプ（水中では浮上、飛行中は上昇） |
| `Shift` | ダッシュ |
| `F` | 飛行の切り替え（`Ctrl` で下降） |
| 左クリック | ブロックを壊す |
| 右クリック | ブロックを置く |
| 中クリック | 狙ったブロックをホットバーに取る |
| `1`–`9` / ホイール | ブロック選択 |
| `F3` | デバッグ表示 |
| `Esc` | メニュー（保存もここから） |

編集内容は localStorage に自動保存され、次回はシードごと復元されます。メニューでシードを入れ替えれば別の世界を作れます。

## 実装

```
src/
  constants.ts  チャンクサイズ・描画距離・フレーム予算
  blocks.ts     ブロック定義（色・不透明度・当たり判定）
  noise.ts      シード付き Perlin ノイズ
  worldgen.ts   高さマップ・バイオーム・洞窟・木
  lighting.ts   スカイライトの伝播（BFS）
  mesher.ts     greedy meshing と AO・光
  chunk.ts      16^3 のボクセル配列とその GPU バッファ
  world.ts      チャンクの生成・メッシュ化・破棄のスケジューリング
  player.ts     一人称の移動と AABB の衝突解決
  raycast.ts    ボクセル格子のレイトラバース（DDA）
  sky.ts        カメラに追従する天球
  ui.ts         ホットバーとデバッグ表示
  main.ts       描画ループと入力
```

要点を 3 つ。

**greedy meshing** — チャンクを 3 軸それぞれのスライスに分け、隣り合う同じ面を長方形にまとめます。
16x16 の平らな床は 512 枚の三角形ではなく 2 枚になります。ブロック ID・向き・AO をまとめて 1 つの整数に詰め、
それが完全に一致する面だけを統合しています。

**AO（アンビエントオクルージョン）** — 面の四隅ごとに、外側の 3 マス（辺 2 つと角 1 つ）が埋まっているかで
0〜3 段階の陰影を決め、頂点色に焼き込んでいます。ライトを 1 つも置かずに立体感が出るのはこれのためです。
そのぶんマテリアルは `MeshBasicMaterial` 1 枚で済み、シェーダの負荷はほぼゼロです。

**スカイライト** — 「真上に遮るものが無いボクセル」を光源とし、そこから 6 方向へ 1 マスにつき 1
（水中は 3）減衰しながら BFS で広げます。洞窟は光源から遠いので暗く、入口の周りだけ光が染み込みます。
深さで一律に暗くする方式だと、崖の途中の洞窟や木の下まで真っ暗になってしまうので、実際に光を伝播させています。
ブロックを置いたり壊したりしたときは、消える光と増える光をそれぞれ BFS でたどって差分だけ塗り直します。

**フレーム予算** — 地形生成もメッシュ化も 1 チャンクあたり約 1ms かかります。個数で区切るとフレームが飛ぶので、
`world.update()` は時間（生成 3ms・メッシュ化 6ms）で区切って続きを次のフレームに回します。
また、メッシュ化には隣接する 8 列のボクセルが必要なので、ボクセルだけは描画距離より 1 リング広く用意し、
隣が揃っていないチャンクは同期生成せずに後回しにしています（ここを手抜きすると数十 ms のスパイクが出ます）。

## 確認

```bash
npm test       # 生成・メッシュ化・光・物理・ストリーミングの検証（109 項目）
npm run bench  # 生成とメッシュ化の速度計測
npm run build  # 型チェック + 本番ビルド
```

`npm test` は WebGL 無しで走ります。頂点の巡回順と法線の一致（ずれると裏面カリングで面が消える）や、
描画距離内にメッシュ化されないチャンクが残らないことなど、画面を見ないと気付きにくい部分を押さえています。
実際の見た目の確認はブラウザで行ってください。

計測例（Node 22 / WSL2）:

```
generateChunk   0.93 ms/チャンク
buildChunkMesh  1.14 ms/チャンク (888 三角形)
world.update    平均 3.0 ms / 最悪 10.2 ms（歩行中のストリーミング込み）
```

## デプロイ

`master` に push すると `.github/workflows/deploy.yml` が走り、`npm ci` → `npm test` → `npm run build`
を通ってから `dist/` が GitHub Pages に配信されます。テストが落ちればデプロイはされません。
手動で回すときは Actions タブの "Run workflow"、または `gh workflow run deploy.yml` です。

サーバーも DB も無く、セーブは localStorage なので、置くものは `dist/` の 3 ファイル
（`index.html` と JS・CSS 各 1 つ、合計 511 kB / gzip 134 kB）だけです。JS のほとんどは three.js 本体で、
初回だけ一括ダウンロードになります。

`vite.config.ts` の `base: "./"` は**相対パスにするためのもの**です。GitHub Pages は
`https://<user>.github.io/<repo>/` というサブディレクトリ配信なので、既定の `base: "/"` のままだと
アセットの参照先が `/assets/...` になって 404 になります。ここを絶対パスに戻すなら、
リポジトリ名を含む `base` を指定してください。

他のホスティング（Cloudflare Pages / Netlify / Vercel、あるいは nginx で `dist/` を配るだけ）でも
同じものがそのまま動きます。ビルドコマンド `npm run build`、出力ディレクトリ `dist` を指定するだけです。

## 調整できるところ

洞窟の暗さは `src/constants.ts` の `AMBIENT_LIGHT`（光量 0 の場所の明るさ、既定 0.16）と
`LIGHT_FALLOFF`（暗がりへの落ち込みの急さ、既定 1.4）で決まります。暗すぎると感じたら
`AMBIENT_LIGHT` を 0.25 くらいまで上げてください。

`RENDER_DISTANCE`（描画距離）と `CHUNK_LAYERS`（世界の高さ）も同じファイルにあります。
地形の性格は `src/worldgen.ts` の `heightAt()` にまとまっていて、大陸・丘・尾根の 3 つのノイズを混ぜています。
ブロックを増やすときは `src/blocks.ts` に定義を足して `PALETTE` に並べれば、ホットバーにも出ます。
