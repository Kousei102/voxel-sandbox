## 音

**外部アセットは使いません。波形も実行時に作ります**（`crack.ts` がテクスチャで同じことをしています）。

**スピーカーはありませんが、波形は確かめられます。** `OfflineAudioContext`
（音声デバイスを使わず配列に書き出すだけの `AudioContext`）に鳴らして数値で見ています
（`test/audio.test.ts`。実装は devDependency の `node-web-audio-api`）。
**ブラウザと同じ仕様の実装なので、`exponentialRampToValueAtTime(0)` のような
仕様違反もちゃんと例外になります** —— 自前の偽物を書くとその手の間違いを素通しします。

**これだけが唯一のネイティブ依存です。** `node-web-audio-api` の `.node` は読み込む瞬間に
`libasound.so.2`（ALSA）を dlopen し、**無い箱ではプロセスごと落ちます**（例外ではありません）。
そのため `test/audio.test.ts` は**動的 import + try/catch** にしてあり、読めなければ
`harness.ts` の `skip()` で音のグループだけ飛ばします。**静的 import に戻さないこと** ——
戻すと、ALSA の無い箱で**音と関係のない 1100 件までまとめて落ちます**（実際に踏みました）。
入れるなら `sudo apt-get install -y libasound2t64`。

**波形のテストが 1 度だけ落ちたことがあります**（2026-08-21、「cutoff が低い材質ほど
こもって鳴る」）。同じコードで**続けて 2 回走らせると両方とも同じ数値で通った**ので、
退行としては扱っていません（`npm test` と `npm run bench` を並べて回していた最中でした）。
**落ちたらまずもう一度走らせること。** 2 回続けて落ちたときだけ退行として扱います。

**`skip()` したものは「すべて成功」の最後にもう一度出ます。** 黙って飛ばすと、その領域の
見張りが外れたまま何周も進んでしまうためです。

| ファイル | 中身 | 確かめ方 |
| --- | --- | --- |
| `sfx.ts` | 何を・いつ・どんな数値で鳴らすか（表と間隔の判断） | `npm test` |
| `audio.ts` | `AudioContext` とノードグラフ | `npm test`（波形）+ 耳（**最後は人**） |

- **`AudioContext` の差し替え口は `AudioEngine` のコンストラクタ 1 つだけです。**
  テストが `OfflineAudioContext` を渡すためのもので、**増やさないこと**
  （増やすと「耳でしか確かめられない部分」がファイルの外へ漏れます）。
- **テストの中でノードを組まないこと。** 必ず `AudioEngine` に鳴らさせます
  （組むと、テストが自分の書いたものに合格するだけになります）。
- 波形で見ているのは **「鳴るか」「長さぶんで止まるか」「音量が掛かるか」
  「水中でこもるか」「材質の `cutoff` が効いているか」**。
  **「気持ちいいか」は測れません** —— そこは今までどおり人に聞いてもらいます。
- 明るさの目安（隣り合うサンプルの差）は**ノイズの割合も一緒に拾います。**
  `cutoff` だけを比べるなら、**ノイズの割合が同じ材質どうし**にしてください
  （ガラスは cutoff 6000 なのに、トーン寄りなので石より数字が小さく出ます）。
- 乱数は **1 発ごとに撒き直します。** 続きの乱数で鳴らすと、音量だけを変えた 2 発が
  別の音になって比べられません。**定数にはしないこと** —— ノイズの波形も
  `Math.random()` で作っているので、定数にすると白色ノイズが直流（無音）になります。

- **`sfx.ts` に WebAudio を持ち込まないこと。** 逆に、**判断を `audio.ts` や `main.ts` に
  書かないこと**も同じ理由で禁止です。
- 音色は `BlockDef.sound`（材質グループ）× 出来事の 2 段で決まります。**材質の既定は `"stone"`**
  なので、柔らかいものには必ず書いてください（書き忘れると「石の音がする」形で静かに間違えます。
  テストが全ブロックの割り当てを一覧で出します）。
- 足音は**時間ではなく歩いた距離で刻みます**（`StepCadence`）。スプリントすれば自然に速くなり、
  壁に押し付けて足踏みしても鳴りません。空中・水中では溜めもしません
  （溜めると着地した瞬間に足音が着地音と重なります）。
- **足音・着地・水しぶきの入口は `Footsteps` 1 つです**（`sfx.ts`）。
  **「前のフレームはどうだったか」もこのクラスが持ちます** —— `main.ts` に置くと、鳴らす条件
  （着地した瞬間・水面をまたいだ瞬間）がブラウザでしか確かめられなくなります。`main.ts` は
  事実（動いた距離・足元の材質・`playing`）を渡して、返った `Cue` を鳴らすだけ。
  **1 フレームに 1 回だけ呼ぶこと**（2 回呼ぶと「前のフレーム」が同じフレームになります）。
  位置を飛ばしたら `reset()`（`main.ts` の `resetFootprint()` が呼びます）。
- 掘っている間のコツコツ音は**採掘の進み具合**で刻みます（`DigCadence`）。硬いブロックほど間隔が空きます。
- `AudioContext` は**最初のクリックの中で**起こします（ブラウザの自動再生制限）。
  `requestLock()` がその入口です。
- 音量はメニューのスライダ（`#volume`）で、セーブに持ちます。**0 で完全に切れること。**
  音は好みが分かれるので、切る手段を必ず残してください。
- 水中は全体をローパスでこもらせます（`setUnderwater`）。判定は `daynight.ts` の
  `environmentFor()` が返す `headInWater`（カメラ位置のブロック）で、フォグと同じものを
  使い回しています。**液体すべてに広げないこと**（溶岩の中で音がこもります）。
