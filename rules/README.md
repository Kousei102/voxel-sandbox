# 決まりごと（層 2）

**領域別の決まりごとはここに置きます。** どの作業でも要るものは `CLAUDE.md`（層 1）、
順番に沿ってやる手順は `.claude/skills/`（層 3）。

## 触る前に、当たるものを読むこと

**各ファイルの先頭の `paths` が、その決まりごとの効くファイル**です。
**自動では読み込まれません** —— 触る前に**自分で引いて読むこと**（引き方は 1 行）:

```bash
grep -l '"src/player.ts"' rules/*.md
# → rules/blocks-shapes.md  rules/mobs.md  rules/vitals.md
```

**二重引用符ごと**引くこと（`paths` の行は `  - "src/player.ts"` の形です）。
引用符を外すと、本文中で名前を挙げているだけのファイルまで釣れます。

- **`test/**` を触るなら `testing.md` を必ず読むこと。** `paths` が `test/**/*.ts` の
  glob なので、上の引き方では出てきません。
- **当たったものは全部読むこと。** `player.ts` を触ったときに `mobs.md` の
  「水中 0.6 倍」が目に入る、という**横断的な気付きが実際にバグを見つけています。**
  多いのは `src/main.ts`（8 本）ですが、あそこが配線の集まる場所だからで、
  **減らすなら `main.ts` の側から判断を出すのが筋**です。

## 直すとき

- **普通に `Edit` / `Write` で直してかまいません。** 無人の周も同じです。
  スクリプトも受け渡し用のファイルも通しません（**踏んだ落とし穴はその周のうちに据えること**。
  `docs/` に書き置いて次へ回さない）。
- **`paths` を必ず書くこと。** 無いものは `npm test` が落とします。
- **`paths` は広めでよい。** 関わるファイルを削らないこと（上の「横断的な気付き」）。
- **同じことを 2 つの層に書かないこと。** 食い違ったときにどちらが勝つか決まりません。
  層 1 は要点だけを持ち、細部はここへ置いて名前で参照します。
- **ファイルを新しく足したら、下の一覧に 1 行足すこと**（`npm test` が突き合わせています）。
- **消すのと `paths` を狭めるのは人に聞くこと。** 足す・直すのは自由です。

## なぜ `.claude/rules/` から出したか（2026-09-04）

**前はここが `.claude/rules/` で、`paths` に当たるファイルを `Read` / `Edit` した瞬間に
Claude Code が自動で読み込んでいました。** 自動なのは良かったのですが、
**`.claude/**` は `Edit` / `Write` に「sensitive file」の確認が出る場所**で
（許可行では消えません。2026-08-25 実測）、**答える人が居ない無人の周はそこで止まります。**

そこで迂回路として `scripts/install-rule.mjs` を置きましたが、**無人の周が使った回数は 0 回**で、
残ったのは手順の複雑さと、**リポジトリの外にある定期実行のプロンプト**（「`.claude/**` に
1 行も書くな」）との食い違いだけでした（AUTODEV 19 が `HANDOFF.md` に報告）。

**縛りとしても機能していません** —— 層 2 より強い `CLAUDE.md`（層 1）は元から自由に
編集でき、迂回用のスクリプト自身も周が編集できました。**編集させたいものを編集できない
場所に置いていた**ので、置き場所のほうを直しました。

引き換えに**自動読み込みを捨てています。** そのぶんは上の `grep` と `npm test`
（`test/rules.test.ts`）で見える形にしました —— **自動読み込みは効かなくても静かでしたが、
一覧と `paths` の食い違いはテストが赤くします。**

**層 3（`.claude/skills/`）は動かせません**（`.claude/skills/` の外に置くと呼び出せない）。
スキルの更新だけは今までどおり `RULES-INBOX.md` 経由で人が取り込みます。
