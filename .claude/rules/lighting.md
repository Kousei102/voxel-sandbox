## 光（スカイライトとブロックライト）

光は **2 系統**あります。広がり方（6 方向 BFS・1 マスにつき 1、水中は 3）は共通で、
違いは光源と、昼夜の影響を受けるかどうかだけです。`lighting.ts` の BFS は
`channel` 引数で両方に使い回します。

| | 光源 | 昼夜 |
| --- | --- | --- |
| スカイライト | 真上に遮るものが無いボクセル | 暗くなる |
| ブロックライト | 松明（`blocks.ts` の `emission`） | 変わらない |

**この 2 つを 1 本にまとめて `max` を取ってはいけません。** まとめた時点で
「これは昼夜で暗くしてよい光か」が失われ、夜や洞窟で松明まで暗くなります。
だからチャンクは `skyLight` と `blockLight` の 2 本を持ち、メッシュにも
`voxelLight`（vec2）として 2 成分のまま載せ、**合成は描画時に GPU でやります**
（`terrainshader.ts` の `max(sky * 昼夜の色, block)`）。

- ブロックライトの明るさ曲線に **`AMBIENT_LIGHT` の下限を入れないこと。** 入れると
  `max` で全体が底上げされ、夜も洞窟も暗くならなくなります（`mesher.ts` の `BLOCK_SHADE`）。
- 光源はごく稀なので、`Chunk.hasBlockLight` が立っていない段は隣の列からの種まきを丸ごと飛ばし、
  `buildChunkMesh` も blockPad が全部 0 なら 4 隅の平均を省きます。この 2 つを外すと
  松明を 1 本も置いていなくても生成が 1 割ほど遅くなります。
- 松明は `supportFace`（支えが要る向き）を持ちます。**置く側（`canPlaceAt`）と
  壊す側（`breakUnsupported`）は必ず対で直すこと。** 片方だけ直すと壁の松明が空中に残ります。
  支えを失って壊れたぶんは `World.onAutoBreak` で外へ知らせ、`main.ts` が地面に落とします。
  **`world.ts` に「何を落とすか」を書かないこと**（あそこはストリーミングのファイルです）。
- 面番号の規約は `blocks.ts` の `FACE_*` と `lighting.ts` の `OFFSETS` の 2 か所に出てきます。
  並びが一致していることをテストで押さえています（ずれると支えの向きと壊れる向きが食い違う）。

### スカイライト固有の話

光源は **「真上に遮るものが無いボクセル」** で、そこから 6 方向へ BFS で広がります。

- 「真下へは減衰しない」という Minecraft の特例は**入れていません。**
  代わりに光源の判定を (x,z) ごとの `skyHeights` で持っているので、真上が空いている縦穴は
  底まで最大光量になります（結果として Minecraft と同じ見え方になります）。
  特例が無いぶん、ブロックの置き／壊しの差分更新が素直な BFS 2 本で書けます。
- 差分更新は `relightSkyEdit()`。**消える光の BFS → 増える光の BFS** の順で回します。
  消す側だけ、増やす側だけ、では境界が壊れます。
- `lightColumn()` は 1 列 32,768 ボクセルを触ります。**必ずチャンクの配列を直接なめること。**
  1 マスずつ `getVoxel()` を通す実装にしたら、1 列あたり 8ms かかって描画が引っかかりました。
- 種まき（`seedColumnLight`）は「隣のマスが暗い可能性がある高さ」だけに絞っています。
  光源を全部積むと 1 列で数万件になります。逆に絞りすぎると、あとから読み込まれた列に
  光が流れ込まず、崖の洞窟の入口が暗いままになります。

明るさは `AMBIENT_LIGHT`（スカイライト 0 のときの明るさ）と `LIGHT_FALLOFF` で決まります。
`AMBIENT_LIGHT` を 0 にすると、松明を持たずに入った洞窟が完全な暗闇になります。
下げるなら、松明が手に入る前（＝石炭を掘る前）に何も見えなくならないか確かめてください。

## 昼夜サイクル

時刻 `t` は `[0, 1)` で、**0 = 日の出、0.25 = 南中、0.5 = 日没、0.75 = 真夜中**（`clock()` では 06:00 起点）。
1 周 20 分（`DAY_LENGTH_SECONDS`）。

- **時刻に関する計算は全部 `daynight.ts` に置くこと。** three の `Color` と `Vector3` しか使っていないので
  ヘッドレスで検証できます。`sky.ts` 側は出てきた値を貼るだけにしてください（判定を散らすとテストが効かなくなります）。
- 地形の明るさは `world.setDaylight()` → シェーダの `uDaylight`。**スカイライトにだけ**掛かるので、
  焼き込んだ光量をそのままに再メッシュ化ゼロで夜にできます。**時刻ごとに頂点色を焼き直す実装にしないでください。**
  松明が夜も暗くならないのはこの掛け先を分けているからです（「光」の節を参照）。
- `NIGHT_BRIGHTNESS` は `AMBIENT_LIGHT` と同じ理由で 0 にできません。夜は全体が 0.28 倍になるので、
  洞窟の見え方は実質 `AMBIENT_LIGHT × NIGHT_BRIGHTNESS` です。
- フォグの色は `dayNight.horizon` に追従させます。天球の地平線と色がずれるとチャンクの出現が見えます。
  **どの色でどれだけ濃いか・液体に浸かっているかを決めるのは `daynight.ts` の
  `environmentFor()` 1 本**で、`main.ts` は引いて貼るだけです。**返るのは使い回しの 1 個**なので、
  値は引いたらすぐ控えること（2 回目の呼び出しで 1 回目の結果まで書き換わります）。
- 太陽・月は板ポリ、星は `Points`。**テクスチャは使いません**（`sky.ts` の GLSL は天球の
  グラデーションだけで、昼夜のために手を入れていません）。天体は `transparent: true` なので
  不透明の地形より後に描かれ、深度テストで山の陰に隠れます。
- 明るさが不連続に飛ぶと「急に暗転する」形でしか気付けないので、1 分刻みの変化量をテストで押さえています。


## GLSL をこの環境で触るとき

**シェーダを手書き／`onBeforeCompile` で注入する変更は、ここでは検証できません。**
GLSL のコンパイルエラーは画面が真っ黒になる形でしか現れないため、入れるなら
ユーザーに確認してもらう前提で、小さく切り出してください。

現状 GLSL は 2 か所だけです。`sky.ts`（天球のグラデーション）と `terrainshader.ts`
（地形の光の合成 3 行）。**地形側を増やすときは `terrainshader.ts` の中だけにしてください。**
差し込み先の shader chunk 名（`#include <common>` など）が three の更新で変わると、
`String.replace` が黙って何もせず画面が真っ黒になります。そうならないよう
`patchTerrainShader` は差し込み先が無ければ例外にし、テストで押さえています。

テクスチャ（`ROADMAP.md`）はここに正面から当たります。入れるときは `terrainshader.ts` を
育てる形にして、**小刻みにユーザーへ見てもらってください。**
