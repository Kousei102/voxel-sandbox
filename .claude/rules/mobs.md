## モブ

判断は `mobs.ts` に全部あります。**新しい GLSL・WebAudio・DOM を 1 行も足していません**
（見張りは `test/mobs.test.ts`）。

| ファイル | 中身 | 確かめ方 |
| --- | --- | --- |
| `physics.ts` | AABB の移動（プレイヤーとモブで共有） | `npm test` |
| `mobs.ts` | **判断は全部ここ。** 表・AI・湧き・戦闘の数値・ドロップ・歩行位相 | `npm test` |
| `mobmesh.ts` | モデル → `MeshArrays`。**three を import しない** | `npm test` |
| `mobrender.ts` | three だけ（`Group` / `Mesh` / マテリアル / 毎フレームの同期）。**判断を書かない** | ブラウザ |

- **モブは保存しません。** 地形と同じ筋（作り直せるものは持たない）です。落ちたアイテムは
  逆に保存します（あちらは作り直せないため。`rules/drops.md`）。読み込み直後は 0 体で、
  `mobs.populate()` のまとめ打ちで戻します。名前付き・手懐けたモブが出たらこの判断を見直してください。
- **湧きの明るさは `spawnLight()` = `max(sky * 明るさ, block)`。シェーダの合成
  （`terrainshader.ts`）とまったく同じ式に保つこと。** ずれた瞬間、明るく見える所にゾンビが湧きます。
  この 1 本で「夜の外は危ない／松明の周りは安全／洞窟は昼でも危ない」が同時に決まります。
  受動モブだけは**明るさを掛けない生のスカイライト**で見ます（掛けると夜に湧かず、朝には世界が空になります）。
- **モブは `world.setVoxel` を呼びません。** `edits` は「プレイヤーがやったこと」でなければならず、
  セーブがそれに乗っています。
- **モブはプレイヤーを押しません**（殴ったときのノックバックだけ）。押し続けると `collides()` の
  押し戻しと喧嘩して壁にめり込みます。モブ同士の当たり判定も入れていません（O(N²) でジッタも出ます）。
- **`DESPAWN_DISTANCE`(72) < `UNLOAD_DISTANCE * CHUNK_SIZE`(160) であること。** 逆転すると、
  ボクセルの無い列にモブが立ち（`getVoxel` が AIR を返す）、世界を突き抜けて落ちます。
- 昼夜の色は `World.daylightUniform()` の**同じ uniform オブジェクトを共有**します。別に持つと、
  モブだけ足元のブロックと違う明るさになります。被弾の赤と炎上の橙は `MeshBasicMaterial.color`
  （光の合成より前に掛かる）なので、**シェーダは要りません。**
- 形は**軸に平行なまま作って `Object3D` で回します**。`Builder.quad()` の「法線の成分の和で
  巡回順を決める」規約は形を作るときの制約で、`Object3D` の変換には掛かりません（回転は行列式 +1）。
  **振る部位の箱は `y1 === 0`**（軸からぶら下げる）。0 でないと足首・肘で回ります。
- **プレイヤーに掛かっている補正は、モブにも要るかどうかを必ず見ること。** 当たり判定と移動は
  `physics.ts` で共有していますが、**重力・終端速度・水中の速さ（0.6 倍）は `player.ts` と
  `mobs.ts` が別々に持っています**（プレイヤーは入力から、モブは AI から速度を作るため）。
  水中の 0.6 倍が抜けていて、ゾンビが水中でも陸と同じ速さで追ってきたことがあります。
  倍率がずれると追いかけっこの勝敗が一方的になります（必ず振り切れる／絶対に振り切れない）。
- 段差登り（`BodySize.step`）で越えられない壁は**跳んで**越えます。跳ぶ材料は
  `moveBody()` の戻り値（横で押し戻されたか）ひとつだけです。**跳ぶときに前へ出す速さを
  入れ直すこと** —— 壁に当たった時点で横の速度は 0 にされていて、空中の加速では戻らないので、
  入れないと真上に跳んで壁の前に落ち続けます（`hopTimer`）。跳べるのは 1 ブロックまでで、
  2 段の壁は越えられません（越えられると囲いの意味が無くなります）。どちらもテストで押さえています。
- モブの費用は **`world.update()` の外**に置いてあります（意図的）。中に入れると
  `test/world.test.ts` の p99 に乗って、モブの退行とストリーミングの退行が区別できません。
- クリエイティブの無敵は **`Vitals` ではなく `Mobs` 側で弾きます**（`Vitals.damage()` は
  もともと `invulnerable` を見ていません）。
- ダメージの音・赤い明滅・死亡画面はモブ用に書き分けていません。**`vitals.takeDamage()` で
  1 回だけ拾う**ので、誰がいつ体力を減らしても同じ経路に乗ります。
  **「フレームの前後で体力を比べる」書き方に戻さないこと。** モブは `updateVitals()` より
  前に走るので、控えを取った時点で差分がもう済んでいて、**ゾンビに殺されても死亡画面が
  出ません**（実際にそうなっていました。`test/vitals.test.ts` が押さえています）。
- ゾンビの日光は**スカイライトが最大の所だけ**（屋根・木の下・液体の中では燃えません）。
  焼死では `onDrop` を鳴らしません（遠くで勝手に焼けた肉が地面に湧いてはいけません）。
- **溶岩は敵味方の区別なく焼きます**（日光は敵対だけ）。豚が溶岩の上を平気で泳いでいると、
  プレイヤーだけが焼ける理由がなくなります。速さは日光の 4 倍（`LAVA_DAMAGE`）で、
  **同じ 2 にするとゾンビが溶岩を泳いで渡ってきます**。焼死のドロップ無しは日光と同じ扱いです。
- **溶岩から上がったあとの長さは `vitals.ts` の `BURN_SECONDS` を共有します**（`LAVA_LINGER`）。
  **日陰用の `BURN_LINGER`(2) を使い回さないこと** —— あれは「木の下でちらつかせない」ための値で、
  使い回すと**同じ溶岩から上がってもモブだけ 2 秒で火が消えます**（実際そうなっていました）。
- **燃えている残り時間は `Math.max` で伸ばすこと。** 代入にすると、溶岩から上がったモブが
  日向へ出た瞬間に残り 15 秒が 2 秒へ**縮みます**（長いほうが勝つのが正しい）。
- **液体の中には湧かせません**（`isLiquid()`）。水なら溺れ、溶岩なら焼けるだけで、
  どちらも「湧いた瞬間に死ぬモブ」を作り続けることになります。
