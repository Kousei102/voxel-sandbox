## ベッドとリスポーン地点

**「1 個のブロックが 2 マスにまたがる」初めての例です。** 大きいチェスト（54 枠）を
入れるときも同じ形にしてください（あちらは「位置ごとの状態」も 2 マスにまたがるので、
`chests.ts` 側にも手が要ります）。

| ファイル | 中身 | 確かめ方 |
| --- | --- | --- |
| `blocks.ts` | 8 状態（足側 4 向き + 枕側 4 向き）と `bedPartner()`。**形の話だけ** | `npm test` |
| `beds.ts` | **判断は全部ここ。** 2 マスを揃えて置く／壊す・リスポーン地点・寝られるかの振り分け | `npm test` |
| `daynight.ts` | `canSleep()` と `WAKE_TIME`（**時刻の判断はここ**） | `npm test` |
| `mobs.ts` | `hostileNear()`（半径は渡される） | `npm test` |
| `main.ts` | 繋ぎだけ | ブラウザ |

- **足側と枕側を別のブロック ID にしてあります。** `BlockDef` は面ごとに 3 色
  （上面・側面・下面）しか持てないので、**枕を白くできるのは 2 マスに分けたときだけ**です。
  枕側は `variantOf: BED` なので、アイテム・ドロップ・名前は「ベッド」1 つに揃います
  （壁掛け松明・点火中のかまどとまったく同じ仕掛け）。
- **`beds.ts` は `World` を丸ごと受け取りません**（`getVoxel` / `setVoxel` / `canPlaceAt` の
  3 つだけ）。**かまど・チェスト・落とし物と違ってワールドを書き換えます** ——
  ベッドを置く／壊すのはプレイヤーの操作そのもので、`edits` に乗るべきものだからです。
- **守っているのは 1 つだけ: 足側と枕側が必ず揃っている。** 崩れると「半分だけのベッド」が
  残り、相方を探す側が永久に見つけられません。**壊れる経路は 3 つあるので、3 つとも塞ぐこと:**
  1. 置く（`placeBed`）—— **先に 2 マスとも確かめてから書く。** 片方だけ書いて諦めると半分残る
  2. 壊す（`main.ts` の `breakBlock`）—— `clearBedPartner()` で相方も消す。**クリエイティブでも**
  3. 支えを失う（`world.onAutoBreak`）—— 床を掘られた半分だけが消えるので、ここでも相方を消す
- **ドロップは 1 台につき 1 個。** 相方を消す経路は `dropOf` を通らないので、
  `clearBedPartner()` から落とし物を出さないこと。
- **リスポーン地点は足側のマスで覚えます**（枕側だと、相方を辿らずに「まだあるか」を見られません）。
  `bedPartner()` の不変条件は**「相方の相方は自分」**で、テストで固定しています。
- **ベッドが壊されても記録は消しません。** 消えたかどうかは戻るときに `spawnPosition()` が
  確かめて、駄目なら null を返します（呼ぶ側が初期位置に落として理由を出す）。
- **`moveToSpawn()` は `primeAround()` を検証より先に呼ぶこと。** リスポーン地点は遠いことがあり、
  未読み込みの列では `getVoxel` が AIR を返すので、**生きているベッドを「壊されている」と
  誤読します**（`syncFurnaceBlocks()` が `hasColumn()` を見ているのと同じ罠）。
- 立たせるのは**ベッドの上**（`BED_HEIGHT` = 9/16。`PLAYER_SIZE.step` の 0.6 より低いので
  歩いて乗れます）。**頭上 2 マスが埋まっていたら初期位置に落とします** ——
  本家のような周囲の探索はせず、初期位置と同じ「3 マス以上の高さを前提にする」線に揃えてあります。
- **寝ても時間は「進みません」**（時計だけ飛びます）。精錬・空腹・モブは dt で動くので、
  6 時間ぶんの精錬が終わったりはしません。**そこを埋めようとしないこと**（別の仕事です）。
- 寝られるかは `canSleep(t)`（太陽が地平線より下か）。**`main.ts` に `time > 0.5` のような式を
  書かないこと** —— `sample()` の夜の定義と二重管理になります。テストが
  `sunElevation()` と `DayNight.elevation` の一致を毎回見ています。
- モンスターが近いと寝られません（`SLEEP_MONSTER_RADIUS` = 8）。**半径は `beds.ts` が持ち、
  `mobs.ts` は渡された距離で「居るか」を答えるだけ**にしてあります。
  **寝られなくてもリスポーン地点は記録します**（地点だけ取り損なう理由がありません）。
- セーブは `SaveData.bed`（`[x, y, z]`。省略可）と **`SaveData.bedDim`**（次元の名前。
  **オーバーワールドなら省略**）。ベッドそのものは `edits` に入っているので、ここが持つのは
  「**どの次元の**どこで寝たか」だけです。**`bed` の形は変えていません**（`version` は 1 のまま）。
  - **`bedDim` が無ければオーバーワールド**とみなします。ネザーが入る前のセーブは、
    寝た場所が必ずオーバーワールドだったので、これで古いワールドも正しく読めます
  - **`beds.ts` は `dimensions.ts` を import しません**（生成器を引き連れてきます）。
    次元は `daynight.ts` の `setDimension()` と同じで**文字列で受ける**だけで、
    綴りのずれは `test/beds.test.ts` が `DIMENSIONS` と突き合わせています
  - **どの次元へ戻るかは `beds.ts` の判断です**（`respawnDimension()` と `respawnPlan()`）。
    **`main.ts` に `dim === NETHER` のような分岐を書かないこと**
    （`test/ui.test.ts` が `main.ts` の次元の分岐を上限 2 件で数えています）
