## かまどと精錬

**「位置ごとに状態を持つブロック」の初めての例です。** チェスト（下の節）がこの器に
乗った 2 つ目で、醸造台を入れるときも同じ形にしてください。

| ファイル | 中身 | 確かめ方 |
| --- | --- | --- |
| `smelting.ts` | 精錬の表（何が何になる・何が何秒燃える）と `tickFurnace`（純粋） | `npm test` |
| `furnaces.ts` | 位置 → かまど 1 台の対応、まとめて進める、セーブ、壊したときの中身 | `npm test` |
| `craftscreen.ts` | 3 枠の操作（`rules/inventory-screen.md` と同じクラス） | `npm test` |
| `inventoryui.ts` | DOM だけ | ブラウザ |

- **代用を戻しました。** 鉄・金の鉱石は**鉱石のまま落ち**、砂 4 個 → ガラスのクラフトは
  消しました。**どちらかを戻すと精錬を飛ばせる抜け道になります**（テストが両方を押さえています）。
- **木から作れる燃料を必ず残すこと。** 石炭が見つかる前に鉄を焼けないと、かまどを作った意味が
  最初の数十分ぶん遅れます（板 1 枚で 1 個ちょうど焼けます）。
- `tickFurnace()` の順番は **火を減らす → 焼くものが無ければ燃料をくべない → くべる → 焼く**。
  **空焚きで燃料を食わないこと**（Minecraft と同じ）。**出力が満杯なら焼かないこと**
  （焼いてから捨てることになってはいけません）。**材料を抜いたら進み具合を戻すこと**
  （引き継ぐと、入れ替えた瞬間に焼き上がります）。
- **かまどは画面を開いていなくても焼けます。** `playing` だけで止めると、開けた瞬間に
  止まって焼き上がるところを見ていられません（`main.ts` は `playing || screen.isOpen` で回します）。
  `world.update()` の外で回すのはモブ・落とし物と同じ理由です。
- **点火中は別のブロック ID（`FURNACE_LIT`）**にして光らせます。差し替えるのは `main.ts` で、
  **`furnaces.ts` は `world` を書き換えません**（`drops.ts` と同じ制約。テストが見張っています）。
  `syncLit()` は **`setVoxel` が成功したときだけ「合った」ことにします** —— 未読み込みの列では
  書き込みが黙って失敗するので、持ち越さないと「火が消えているのに光ったままのかまど」が残ります。
  列があるかどうかは `world.hasColumn()` で見ること（`getVoxel` は未読み込みで AIR を返すので、
  「かまどが無くなった」と誤読します）。
- **壊したら中身を地面へ出すこと**（`furnaces.remove()` が返します）。**クリエイティブでも出します** ——
  中身は集めたアイテムで、壊し方によって消えてよいものではありません。落ちたアイテムの仕組みが
  無かったら、この判断はそもそも取れませんでした。
- **焼き上がりの枠は取り出し専用。** 置ける経路を 1 つでも残すと（ドラッグ・数字キーも含む）、
  材料でないものが焼き上がりに化けます。`canPlaceInto()` を通してください。
- **画面を閉じてもかまどの中身は返しません。** 盤面（`grid`）は預かり物なのでインベントリへ
  返しますが、かまどの中身は**ワールドの持ち物**です。`returnAll()` で触らないこと。
- セーブは `SaveData.furnaces`（`"x,y,z"` → 9 要素）。**`edits` に混ぜないこと** ——
  あちらは 1 マスにブロック ID 1 個の表です。**空っぽで火も消えているかまどは省きます**
  （右クリックで開いただけのものが溜まらないように）。

## チェスト

**かまどが作った器に乗せた 2 つ目です。** 上の「かまどと精錬」と読み比べれば、
「位置ごとに状態を持つブロック」を足すときの型が分かります。

| ファイル | 中身 | 確かめ方 |
| --- | --- | --- |
| `chests.ts` | **判断は全部ここ。** 27 枠の器・位置ごとの対応・壊したときの中身・セーブ | `npm test` |
| `craftscreen.ts` | 27 枠の操作（かまどと同じクラス。`SlotArea` に `"chest"` を足しただけ） | `npm test` |
| `inventoryui.ts` | DOM だけ | ブラウザ |

- **1 ファイルで済んでいます**（かまどは `smelting.ts` + `furnaces.ts` の 2 つ）。
  分ける理由は「精錬という**純粋な規則**が独立している」ことで、入れ物にはそれがありません。
  **`update(dt)` も持ちません** —— 毎フレーム進むものが無いので、`main.ts` からも呼びません
  （かまどが `world.update()` の外で回っているのとは事情が違います）。
- **`SlotArea` の `"chest"` は `index` で引く側**です（`grid` / `inv` と同じ）。
  かまどの `input` / `fuel` / `output` が名前で引くのは、**枠ごとに意味が違うから**。
  27 枠は全部対等なので、名前を 27 個作らないこと。
- **全枠が対等**です。かまどの焼き上がり（取り出し専用）のような特例が無いので、
  `canPlaceInto()` に足すものはありません。かき集めのプールにも丸ごと入ります。
- 入れ方は **`inventory.ts` の `addToSlots()` を使い回します**（「同じアイテムの山に先に足す →
  空き枠へ」の 2 パス）。**写さないこと** —— プレイヤーの収納とチェストで入り方が違うと、
  片方だけ直したときに静かに食い違います。
- 画面を開いている間は**盤面が 1 枠も使えません**（`usable()` が false）。
  出ていないスロットに物を入れる経路を残さないためで、かまどとまったく同じ扱いです。
- **開ける器はいつも 1 つだけ。** `openScreen()` / `openFurnace()` / `openChest()` は
  互いを null にします。両方生きていると、画面に無い側へ物が入ります。
- **画面を閉じても中身は返しません**（ワールドの持ち物）。**壊したら地面へ出すこと** ——
  クリエイティブでも出します（かまどと同じ理由）。
- セーブは `SaveData.chests`（`"x,y,z"` → 54 要素）。**空っぽのチェストは省きます。**

## 器の中身は傷ごと持つ

**かまどもチェストも、中に入っている道具の傷を持ちます**（3c-2・2026-09-01）。
**傷が消える経路はもう残っていません** —— つまんで置く・シフトクリック・器を壊す・
読み込み直す・次元をまたぐ、のどれを通っても付いて回ります。

- **セーブは中身の配列を増やさず、省略可キーを別に足す形です**（`SaveData.chestWear` /
  `SaveData.furnaceWear`）。**`serializeChest()` の 54 要素と `serializeFurnace()` の
  9 要素は増やさないこと** —— 増やすと既存のセーブが丸ごとずれます
  （`wear` を `inventory` と分けたのとまったく同じ理由）。`version` は 1 のままです。
  - **キーは `chests` / `furnaces` と同じ `"x,y,z"`**、値の位置は**枠の並びそのまま**
    （チェストは 27 要素、かまどは `input` / `fuel` / `output` の 3 要素）
  - **省く条件も `serialize()` と揃えること**（`isChestEmpty()` / `isIdle()`）。
    ずらすと、**別の台の傷が載ります**
  - **全部新品なら `serializeWear()` が `undefined` を返してキーごと消えます。**
    道具を器に入れていない人のセーブは、耐久値が入る前と 1 バイトも変わりません
- **`deserialize(raw, wear)` を 2 本に分けないこと。** ここが `map` を作り直すので、
  別呼び出しにすると順番を間違えた瞬間に傷だけ消えます（`drops.deserialize()` と同じ形）。
- **`chests.ts` / `furnaces.ts` / `smelting.ts` が `durability.ts` から取ってよいのは
  `damageOf` / `carryWear` / `serializeWear` / `deserializeWear` の 4 本だけ**です。
  `maxUses` / `TOOL_USES` / `wearSlot` が要ったら「**器が耐久値を減らす**」設計に
  なっている合図（減るのは掘ったときだけで、焼いても入れても減りません）。
  `test/chests.test.ts` が 3 ファイルとも見張っています。
- **器の側に `?? 0` を書かないこと。** 傷を読むのは `damageOf()`、載せるのは
  `carryWear()`、丸めるのは `wornValue()` の 1 本ずつです。写した瞬間に
  「棒の山に傷が付く」経路がその場ごとに増えます。
- **壊したときは中身を傷ごと返します**（`remove()` の `{ item, count, damage }`）。
  落とす側（`breaking.ts` の `Burst.damage`）は素通しするだけで、
  「道具かどうか」も「何回で尽きるか」も知りません。
- **山（`count > 1`）に傷を載せる経路を作らないこと。** `addToChest()` の第 4 引数は
  `addToSlots()` へ素通しするだけで、載るのは**空き枠へ入れた 1 個ぶん**です
  （傷が付く物は全部 `stack: 1`）。
- **かまどへのシフトクリック（`craftscreen.ts` の `moveInto()`）にも傷を載せてあります**
  が、**いまの表では道具で届きません** —— 焼けるものにも燃料にも道具が 1 本も
  無いためです。本家のように鉄の道具が焼けるようになった日に黙って新品へ戻らないよう、
  `test/smelting.test.ts` が**呼び出しの形**を見張っています。
