## 立方体でないブロックの形

`BlockDef.boxes` が**そのブロックの形**で、**3 つの用途を兼ねます**。分けて持つと必ず食い違います。

1. 狙う判定（`raycast.ts`）— セルに入っただけでは当たりにせず、箱との交差を見ます。
   **これを省くと、ハーフの上の空間を狙っているのにハーフに当たります**（見えない所に
   ブロックが生え、狙っていないものが壊れる）。
2. 当たり判定（`player.ts`）— `solid` なブロックだけが使います。松明は形を持ちますが
   `solid: false` なので通り抜けます。
3. 見た目 — `model: "boxes"` なら `buildProps()` がこの箱をそのまま積み、
   `model: "cross"` なら**この箱の中心で板 2 枚を交差させます**（草）。
   どちらも `boxes` から引くので、狙う形と見た目がずれません。

- **`collides()` は `isSolid` ではなく `collisionBoxes()` を見ること。** 1x1x1 と決め打ちにすると
  ハーフの上で半ブロック浮きます。押し戻し先は `hitMin` / `hitMax`（直前の `collides()` の結果）
  なので、**間に別の `collides()` を挟まないこと。**
- 段差の自動登りは `STEP_HEIGHT`（0.6）。ハーフ（0.5）は歩いて登れて、立方体（1.0）は登れません。
  **これが無いと階段を置く意味がありません。**
- `canSupport(id, face)` は「その面が端まで埋まっているか」で決まります。だから
  **下付きハーフの上面には松明が付きません**（上付きの上面には付きます）。
- 階段は**ハーフ＋段の 2 個の箱**で、`facing` の側が高くなります（歩いてきた人がそのまま登れる向き）。
  向きは置く人の `yaw` から決めるので、`PlaceContext` に `facing`（`faceFromYaw()` の結果）を渡します。
  上下の反転はハーフとまったく同じ規則（`placedUpper()` を共有）です。**片方だけ変えないこと。**
- `canSupport()` は**箱 1 個で面が埋まっているか**しか見ません。だから階段の高いほうの側面は
  ハーフと段の 2 個で埋まっていても支えになりません（松明が付きません）。
  判定を「箱の合併」にすると重くなるうえ、AO や光の扱いとも噛み合いません。
  **意図的にこうしてあります。**
- 選択枠とひび割れは `shapeBounds()`（形を囲む箱）に合わせます。1x1x1 のまま出すと、
  ハーフの上の何も無い所に枠とひびが浮きます。**囲む箱**なので階段では立方体のまま出ますが、
  形どおりに縁取るには枠を箱ごとに出す必要があり、そこまでの価値はないと判断しています。
- 置く**マス**の判定は `placeSpot()`、置く**向き**の判定は `placedVariant()` に集約します。
  **`main.ts` に散らさないこと**（置く側と壊す側で条件が食い違っても気付けませんし、
  DOM 込みでしか確かめられなくなります）。
  `placeSpot()` は狙ったブロックが `replaceable` なら**そのマス自身**を返します。
  隣（法線の側）に置くと、草むらが残ったまま横にブロックが生えます。
  そのとき支えは必ず真下です（狙った面をそのまま支えにすると、横から狙ったときに
  何も無い側を支えにしてしまいます）。
  **手に持ったものを実際に置く／火を点ける判断は `placing.ts`**（`tryPlace` / `tryIgnite`）で、
  `main.ts` は結果（`"none"` / `"blocked"` / `"placed"`）を貼るだけです。
  受け取るのは `World` ではなく `getVoxel` / `setVoxel` / `canPlaceAt` の 3 つと、
  **体（`overlapsBlock`）1 つ**だけ —— だから「自分の居る所に置けない」も
  「支えが無ければ置けない」もヘッドレスで確かめられます
  （`test/placing.test.ts` が `main.ts` に `canPlaceAt` が戻っていないことを見張っています）。
  **置けない理由は文字列で返すこと**（黙って何も起きないと、何が悪いのか分かりません）。
  ベッドのような 2 マスのものは**片方だけ書かない**（`beds.ts` に任せる。`rules/beds.md`）。
- ハーフ・階段は `opaque: false` にしたうえで **`blocksSky: true`** にします。
  でないとハーフで葺いた屋根の下が昼のまま明るくなります。草は逆に `blocksSky: false`
  （止めると、草の生えた地面だけが一段暗くなります）。
- 草のように「置いたら黙って消えてよい」ものは **`replaceable: true`**。
  設置（`main.ts`）と木の枝葉のスタンプ（`worldgen.ts`）が**同じ `isReplaceable()`** を見ます。
  片方だけにすると、木の下の葉が草むらに当たって欠けます。
- **液体（水・溶岩）は `liquid: true` で、判定は `isLiquid()` 1 本に聞くこと。**
  この 1 つで決まるのは: 狙う光線が素通りする（`raycast.ts`）/ 松明とベッドを差し込めない
  （`main.ts` / `beds.ts`）/ 頭が浸かるとフォグが掛かる（`fog`。色と濃さは `BlockDef` が持ち、
  `main.ts` は貼るだけ）/ アイテムにならない（`items.ts`）/ 泳ぎと浮力（`player.ts` の
  `inLiquid`・`mobs.ts`・`drops.ts`）/ そこに湧かない（`mobs.ts`）。
  **`id === WATER` と書かないこと** —— 溶岩を足したとき 3 か所とも直し忘れて、
  **溶岩湖の向こうを狙うと手前の溶岩が置き場になりました**
  （水は素通りするので底の石の上に置かれます）。`test/blocks.test.ts` が
  **`raycast.ts` / `mobs.ts` / `drops.ts` / `beds.ts` に液体の名前（`WATER` / `LAVA`）が
  戻っていないか**を見張っています。
- **水と溶岩がぶつかると黒曜石になります。** 規則は `blocks.ts` の **`quenched(id, 隣)`**
  （純粋・座標を知らない）で、**どのマスに効くかは `liquids.ts` の `quenchAround()`**、
  `main.ts` は流した直後に 1 行呼ぶだけです。`beds.ts` と同じで `World` を丸ごと受け取らず
  `getVoxel` / `setVoxel` の 2 つだけを受けます。
  - **`quenched()` は「熱い液体 + 熱くない液体」で決めます**（`isHotLiquid()` の表 1 本）。
    `id === LAVA` と書き始めると、液体を足したときに必ず片方を忘れます。
    `test/liquids.test.ts` が **`liquids.ts` に `WATER` / `LAVA` / `OBSIDIAN` が
    出てこないこと**を見張っています
  - **置いたマス自身と隣の 6 マスの両方を見ること。** 片方だけだと
    「溶岩に水をかける」と「水に溶岩を流す」のどちらかだけが効きます
  - **流れは実装していないので、固まるのはバケツで流した瞬間だけです。**
    生成では水（海面 40）と溶岩（10）が触れないので、これで導線は足ります
- **焼ける液体は `hot: true` で、判定は `isHotLiquid()`。** どれだけ焼けるかは `BlockDef` に
  持たせません —— 数値はプレイヤーが `vitals.ts`、モブが `mobs.ts` です
  （**ネザーの溶岩海も同じ `LAVA`** なので、増やすときも表 1 本のままにすること）。
- **水そのものを見てよいのは 3 つだけです: 息（溺れ）・音のこもり・水しぶきの音。**
  液体全部に広げると溶岩で溺れます。逆に `inLiquid` だけで見ると、**溶岩に浸かった瞬間に
  炎が消えます**（消すのは水だけ）。溶岩のダメージと炎上は `rules/vitals.md` の「体力と空腹」に。


## ID の枠の細かい話（`CLAUDE.md` の「ブロック ID の枠」の続き）

64 以降を使えるのは、**`isProp()` が true のブロックが greedy の面マスクに載らない**からです
（`mesher.ts` の可視判定が飛ばすので `encodeFace` を通りません）。向き違いは
`items.ts` がアイテムを作らないので、64 以降の**アイテム** ID（棒・鉱物・道具）とも衝突しません。

**立方体の「状態違い」は 64 以降に置けません。** 点火中のかまど（`FURNACE_LIT`）が
1..63 を 1 個使っているのはそのためです（立方体は `encodeFace` を通るので 63 まで）。
`variantOf` を大元に向けてあるので、アイテムもドロップも名前も増えません。

**水平の 4 向きを持つブロックは、向きの表を `HORIZONTAL_FACINGS` /
`HORIZONTAL_FACING_INDEX` / `HORIZONTAL_STEP` から引くこと**（階段とベッドが共有しています）。
写して 2 か所にすると、並べ替えたときに「階段は合っているのにベッドだけ向きが逆」という
形で静かに壊れます。状態の番号はどちらも `向きの添字 * 2 + もう 1 ビット` で、
もう 1 ビットの意味が階段は「上下反転」、ベッドは「枕側」です。
