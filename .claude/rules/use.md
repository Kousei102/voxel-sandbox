## 右クリックで何が起きるか（`use.ts`）

**マウスの右ボタンには 14 通りの行き先があります**（刈る・作業台・かまど・チェスト・ベッド・
耕す・植える・バケツ・枠にアイを嵌める・アイを投げる・火を点ける・弓を引く・食べる・置く）。
その振り分けは `use.ts` の **`decideUse()` 1 か所**で、three も DOM も `World` も
持ち物も出てきません（見張りは `test/use.test.ts`）。

| ファイル | 中身 | 確かめ方 |
| --- | --- | --- |
| `use.ts` | **振り分けは全部ここ。** 事実（`UseFacts`）→ 注文（`UseAction`） | `npm test` |
| `placing.ts` | 置ける／点けられるかと書き込み（`tryPlace` / `tryIgnite` / `tryBucket`） | `npm test` |
| `main.ts` | 繋ぎだけ（注文を受けて画面・音・持ち物に貼る） | ブラウザ |

- **並び順そのものが判断です。** 入れ替えると静かに壊れるものが 4 つあり、どれも
  現物を狙うまで気付けません:
  1. **刈る（`shear`）がいちばん先。** あとにすると、作業台やチェストの前に立った羊だけ
     刈れません（そこまで追い込まないと気付けない形で壊れます）
  2. **器（作業台・かまど・チェスト・ベッド）が先。** あとにすると、器の上に立って
     ブロックを置こうとしたときに置くほうが勝ち、**作業台が開けなくなります**
  3. **枠にアイを嵌める（`fitEye`）は投げる（`throwEye`）より先。** 逆にすると、
     枠を狙っても手からアイが飛んでいって**永久に嵌まりません**（枠は地下 18 マス）
  4. **バケツは食べ物より先。** どちらも右クリックですが、バケツは押しっぱなしでは
     なく 1 回で終わります

  **クワ（`till`）は器（作業台・かまど・チェスト・ベッド）の次、バケツより前。**
  器より前に出すと、**作業台の上に立ってクワを持っているあいだ作業台が開きません。**
  **耕せるかどうか（土か草か・上が塞がっていないか）はここで決めないこと** ——
  `place` と同じで、可否は `placing.ts` の `tryTill()` です。`decideUse()` は
  「クワを持って何かを狙っている」という事実だけで `till` の注文を出します。

  **種（`plant`）はクワ（`till`）の次、バケツより前。** 「耕す → 植える」の順に並べておくと
  読めます。**植わるかどうか（耕地の上か・塞がっていないか）はここで決めないこと** ——
  `till` とまったく同じで、可否は `placing.ts` の `tryPlant()` です。`decideUse()` は
  「種を持って何かを狙っている」という事実だけで `plant` の注文を出します
  （**土を狙っても `plant` に来ます**。弾くのは `placing.ts` の仕事で、2 か所で弾かないこと）。
- **`aim`（狙っているブロック）が無くても効くものがあります** —— 食べる・弓・バケツ・
  アイを投げる。**空を向いたまま食べられないのはおかしい**ので、`aim` の有無で
  先に弾かないこと。逆に火を点ける・置くは「どのマスか」が要るので `aim` が要ります。
- **`none` と `flash` を分けること**（`placing.ts` の `PlaceOutcome` と同じ理由）。
  黙って何も起きないのと理由を出すのとでは手ごたえがまるで違うので、
  **矢が無い・満腹は必ず `flash` で返します。**
- **置けるかどうかは決めません。** 置けないアイテムも `place`（`base` が `AIR`）で返し、
  可否は `placing.ts` の `tryPlace()` が持ちます。**2 か所で弾かないこと。**
- **クリエイティブぶんは呼ぶ側で込みにします**（`UseFacts.hasArrow`。`bow.ts` の
  `DrawContext` と同じ約束）。`use.ts` が持ち物を見に行き始めると、
  「矢があるか」の判断が 2 か所になります。
- **`main.ts` に `if` の列を書き戻さないこと。** `test/use.test.ts` が `main.ts` に
  `isBucket(` / `isBow(` / `isFireStarter(` / `isEndPortalFrame(` / `ENDER_EYE` が
  戻っていないかを見張り、`test/ui.test.ts` の `routed` が `decideUse(` と
  `useOrPlace(mobIsNearer(` の**両方**（判断と呼び出しの形）を見張っています。
  - `test/use.test.ts` は `main.ts` に **`isShears(`** が戻っていないかも見ています。
    **`main.ts` が持ってよいのは「刈れるモブが手前に居る」という事実だけ**で、
    どれがシアーズかは `items.ts` の表 1 本です。
  - `test/use.test.ts` は `main.ts` に **`isHoe(`** が戻っていないかも見ています
    （`isShears(` と同じ理由）。
  - `test/use.test.ts` は `main.ts` に **`isSeed(`** が戻っていないかも見ています
    （`isHoe(` / `isShears(` と同じ理由）。**`test/ui.test.ts` の `routed` には
    `["苗を植える", "tryPlant("]`** が入っていて、置ける／置けないの規則が
    `main.ts` へ戻っていないかを見ています。

## 右クリック以外（`controls.ts`）

**キーボードと左・中クリックの振り分けは `controls.ts`** です（`use.ts` とまったく同じ形で、
返すのは注文だけ。見張りは `test/controls.test.ts`）。**並び順そのものが判断**なのも同じで、
崩すと現物を押すまで気付けません:

- **画面（インベントリ・かまど・チェスト・クリエイティブ）が開いている間が先。**
  あとにすると、盤面に物を置くつもりの数字キーで**ホットバーが切り替わり**、
  `Q` は掴んでいる山ではなく**手に持っているブロック**を投げます
- **`Digit` は `switch` より先。** あとに回すと 1..9 が `player.setKey()` へ流れます
- **モブがブロックより手前なら殴る。** 逆にすると、**目の前のゾンビを殴れません**。
  狙っているブロックが無くても降りないこと（空を背にしたモブが殴れなくなります）
- **「手前に居るのはモブか」は `mobIsNearer()` の 1 本**で、左クリック（殴る／掘る）と
  右クリック（刈る／置く）が**同じ関数を呼びます。** `main.ts` に距離の比較を
  書き直すと、殴れる間合いと刈れる間合いが食い違い、**「殴れるのに刈れない羊」**が
  ブラウザを開くまで分かりません。`test/ui.test.ts` の `routed` が
  **`useOrPlace(mobIsNearer(`** という**呼び出しの形**で見張っています
  （`useOrPlace();` のままだと、比較を書き直しても緑で通ります）。
- **既定の動きを止めるかどうか（`prevent`）も向こうが決めます。** `Space` を止め忘れると
  跳ぶたびに画面が下へ飛び、`F3` を止め忘れると開発者ツールが開きます
