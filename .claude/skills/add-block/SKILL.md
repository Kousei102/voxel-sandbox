# ブロック / アイテムを足す

決まりごとの本体は `CLAUDE.md` の「ブロック ID の枠」と `.claude/rules/blocks-shapes.md`。
ここは**手順**だけです。

## 1. ID を取る

**`ROADMAP.md` の「ID の予約表」にある番号だけを使うこと。** 無い番号を使いたくなったら、
そこで止まってユーザーを呼びます（`LOOP.md` の「5. 止まって人を呼ぶ条件」）。

**どれを足すときも 111 以降（`SHARED_ID_START`）から、次の空き番号を 1 つ取ります。**
立方体でも向き違いでもアイテムでも同じ 1 本の番号列で、**1 つの番号は 1 つのものだけ**が取ります
（`test/blocks.test.ts` がブロックとアイテムの両側を突き合わせています）。

| 帯 | 中身 | 取れるか |
| --- | --- | --- |
| 1..63 | 立方体・持てるブロック（アイテム ID と同じ番号） | **凍結**（予約表に残る 55..63 だけ） |
| 64..110 | `variantOf` を持つ向き違いだけ | **凍結・満杯** |
| **111..255** | ブロックもアイテムも | **ここから取る** |

**既存の番号を振り直さないこと。** `localStorage` の差分にブロック ID がそのまま入っているので、
既存プレイヤーのワールドが別のブロックに化けます。**足すだけ。**

`npm test` が毎回「1..63 の空き」と「111..255 の空き」を出します。着手前に見ておくこと。

## 2. `blocks.ts` に定義する

- **`sound` を必ず書くこと。** 既定は `"stone"` なので、柔らかいものは書き忘れると
  静かに石の音になります（テストが全ブロックの割り当てを一覧で出します）。
- 立方体でないなら `boxes` と `model` を持たせ、**`opaque: false`** にする
  （true だと隣の面が greedy 側で消えて地面が透けます）。
- 屋根になるものは `blocksSky: true`、草のように置いたら消えてよいものは `replaceable: true`。
- 向き違いは `variantOf` を大元へ向ける。こうするとアイテム・ドロップ・名前が増えません。

形・支え・当たり判定の決まりは `.claude/rules/blocks-shapes.md` を読むこと（`boxes` が
狙う判定・当たり判定・見た目の 3 つを兼ねます）。

## 3. アイテムとして持てるようにする

`items.ts` がブロック ID と同じ番号でアイテムを作ります。**クリエイティブの一覧は
`allItemIds()` そのまま**なので、ここに乗れば `E` の一覧に自動で出ます。
**別表を手で並べないこと**（足したのに出てこない、が起きます）。

1 山の数は `itemStackLimit()` に聞くこと（`64` と直接書かない）。

## 4. レシピ・精錬・ドロップ

- クラフトは `crafting.ts`。形ありレシピは**盤面もレシピも空の行・列を落としてから**比べます。
- 精錬は `smelting.ts`。**精錬を飛ばせる代用レシピを足さないこと**
  （鉱石がそのまま使える、砂 4 個 → ガラス、の類。テストが押さえています）。
- 掘って何が落ちるかは `dropOf`。道具の階層が足りないと**何も落ちません**。

## 5. ハーフ・階段の材質を増やすとき

`blocks.ts` の `slabPair()` と `stairSet()` に **1 行ずつ**、`crafting.ts` に **2 行**。
**階段 1 材質でも「大元」は 1 個だけ**ですが、向き 7 個ぶんの番号も同じ列から取ります（計 8 個）。

## 6. 確かめる

```bash
npm run typecheck
npm test          # 2 帯の空き数、ID 枠の検査、音の割り当て一覧が出る
```

見た目に触れても `REVIEW.md` には書きません（あれは**ユーザーが通しで遊んで見つけた不具合**の置き場です）。
代わりに `HANDOFF.md` に「何が見た目に出るか」を 2〜3 行残すこと。
