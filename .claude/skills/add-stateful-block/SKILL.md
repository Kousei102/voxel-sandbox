# 位置ごとに状態を持つブロック / 器を足す

先例は**かまど**（`smelting.ts` + `furnaces.ts`）と**チェスト**（`chests.ts` 1 本）。
決まりごとの本体は `.claude/rules/stateful-blocks.md` と `.claude/rules/inventory-screen.md`。
ここは**手順**だけです。

## 1. ファイルを分けるかどうかを決める

**純粋な規則が独立していれば 2 ファイル、無ければ 1 ファイル。**

- かまどは「何が何になる・何が何秒燃える」という規則が独立しているので
  `smelting.ts`（純粋）と `furnaces.ts`（位置ごとの対応）に分けています。
- チェストは入れ物なのでそれが無く、`chests.ts` 1 本で済んでいます。
- 毎フレーム進むものが無いなら **`update(dt)` を持たせないこと**（`main.ts` からも呼ばない）。

## 2. ブロックを足す

`add-block` スキルの手順どおり。点火中のかまどのような**見た目の状態違いは別のブロック ID**
にして、`variantOf` で大元へ向けます（1..63 を使う。立方体は `encodeFace` を通るため）。

## 3. 器を `CraftScreen` に足す

**画面ごとにクラスを分けないこと。** `CraftScreen` 1 つのまま `SlotArea` に枠を足し、
`slotAt()` が返せるようにするだけで、掴む・配る・シフトクリック・数字キー・ドラッグ配分が
そのまま効きます。写すと 500 行が二重になって片方だけ壊れます。

- **枠ごとに意味が違うなら名前で引く**（かまどの `input` / `fuel` / `output`）。
  **全部対等なら `index` で引く**（チェストの 27 枠。名前を 27 個作らない）。
- 取り出し専用の枠を作るなら **`canPlaceInto()` を通すこと**。置ける経路を 1 つでも
  残すと（ドラッグ・数字キーも含む）、材料でないものが焼き上がりに化けます。
- **開ける器はいつも 1 つだけ。** `openScreen()` / `openFurnace()` / `openChest()` は
  互いを null にします。両方生きていると画面に無い側へ物が入ります。
- 開けている間は盤面（クラフト）を使わせないなら `usable()` を false に。

## 4. 中身の出し入れ

- 入れ方は **`inventory.ts` の `addToSlots()` を使い回すこと**（同じ山に先に足す → 空き枠へ）。
  写すと、プレイヤーの収納とこの器で入り方が静かに食い違います。
- **画面を閉じても中身は返しません**（ワールドの持ち物）。返すのは盤面（`grid`）だけ。
- **壊したら中身を地面へ出すこと。クリエイティブでも出します。**
  集めたアイテムは壊し方によって消えてよいものではありません。

## 5. ワールドを書き換えてよいか

**原則ダメです。** `edits` は「プレイヤーがやったこと」でなければならず、セーブがそれに乗っています。

- かまどの点火中 ID の差し替えは **`main.ts` がやります**（`furnaces.ts` は `world` を触らない）。
- 例外はベッドのように**置く／壊すのがプレイヤーの操作そのもの**であるもの（`beds.ts`）。
- 未読み込みの列では `setVoxel` が黙って失敗し、`getVoxel` は AIR を返します。
  列があるかは **`world.hasColumn()`** で見ること。

## 6. セーブ

`SaveData` に `"x,y,z"` → 平坦配列のキーを足します（かまどは 9 要素、チェストは 54 要素）。

- **`edits` に混ぜないこと**（あちらは 1 マスにブロック ID 1 個の表）。
- **空っぽのものは省くこと**（開いただけのものが溜まります）。
- **`SaveData.version` は 1 のまま。** 追加キーは「省略可・無ければ既定」に揃えます。

## 7. 確かめる

```bash
npm run typecheck
npm test
```

`test/storage.test.ts` に往復（保存 → 読み込み）を、器の規則に `test/craftscreen.test.ts` を
足すこと。見た目に触れたら、`REVIEW.md` ではなく `HANDOFF.md` に
「何が見た目に出るか」を 2〜3 行残すこと（`REVIEW.md` はユーザーが不具合を書く場所です）。
